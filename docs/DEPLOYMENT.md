# KCDHANUNJAY INFOSYS — one Render service + MongoDB Atlas

## Deploy
1. Create a MongoDB Atlas database, dedicated least-privilege database user, and network access rule that allows your Render service to connect. Atlas free tier and Render service tier availability may change.
2. Copy these files to the root of the existing GitHub repository, commit and push. **Do not commit `.env`**. This package includes the supplied frontend pages and replaces the old frontend proxy `server.js` with an integrated API server.
3. Run `npm install` to generate a `package-lock.json` and commit it. The Render Blueprint uses `npm install --omit=dev` (and can be changed to `npm ci --omit=dev` after committing the lockfile).
4. Render Dashboard → New → Blueprint (or Web Service) → connect repository. Choose Node runtime. Set `MONGODB_URI`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `PAYMENT_PHONE`, `PAYMENT_UPI_ID`. `JWT_SECRET` is generated by the Blueprint or provide a random 32+ character secret for manual deployment.
5. Test `https://YOUR-RENDER-DOMAIN/api/health` and then registration/login. Admin account is created only when no account already uses `ADMIN_EMAIL`.
6. Admin creates an exam via admin dashboard. For `/exam.html?type=...`, ensure the exam's `type` matches the requested type. The current create-exam form has no `type` field, so it defaults to lowercase `subject` or `title`; edit it if needed.

## Implemented
- Single-origin static frontend + Express API, MongoDB Atlas persistence, bcrypt password hashes, JWT sessions, admin role checks.
- Admin exam creation, question entry, JSON upload, JSON bulk import, exam lookup, timed session creation, answer autosave, server-graded result submission, leaderboard ranks, analytics, logs, student management.
- PhonePe manual payment notification, screenshot in MongoDB, admin approve/reject, payment history, revenue/audit. **Never approve solely from a screenshot or UTR: independently confirm bank/UPI settlement.** No payment gateway callback exists.
- Socket.IO authentication and basic proctor alert relay.

## Known limitations and follow-up work
- Existing frontend references additional pages that were not in the uploaded source set (`dashboard.html`, `forgot-password.html`); they are **not** provided. Add them before using those links.
- Existing `student-builds.html` calls `/api/projects/student-builds` and document-generation endpoints; these are not implemented. They return 404 rather than pretending success.
- Online compiler backend and code sandboxing are not implemented. Do not execute untrusted code directly on the Render web process.
- Email test endpoint returns 501 until an email provider is integrated.
- Sample exams require admin-created exam/question content. No copyrighted/sample question bank was invented.
- Sample mode permits anonymous result submission; use authenticated sessions for high-stakes exams. Proctoring signals are browser-reported, not independently verified.
- Question upload accepts JSON arrays, not CSV or Word. Bulk textarea accepts JSON arrays.
- For production, add email verification, password reset, backup/restore, admin MFA, account recovery, stronger abuse protection, audit retention policy, integration tests, and transaction-safe finalization. For paid exams, session autosave is authoritative; ensure answers are saved before submit.
- MongoDB is not deployed on Render: it runs separately in Atlas. This package has not been tested against a live Atlas cluster or Render deployment.

## Security notes
- Never commit credentials, JWT secrets, screenshots or database connection strings.
- API routes under `/api/admin` require valid admin JWT.
- Frontend must not contain answer keys. The API only returns question text/options, while server grading reads stored keys.
- Uploaded screenshot files are kept in MongoDB and available only to authenticated admins.
